缘起：排版这件"小事"吃掉我多少时间

我不是设计师，也不想每次发文都从头调样式。真正让我下定决心的，是那句话——

个人能力的价值，不在于你自己用了多少次，而在于能被复制多少次。

如果排版这件事每次都要手动来一遍，那它永远是个"体力活"。但如果我能把它打包成"输入一篇稿子、输出可粘贴的 HTML"，它就变成了可以复用的资产。

💡 贴士
想清楚"输入什么、输出什么"，比急着写代码重要十倍。我的输入是 .md 或 .docx，输出是一段能直接粘贴进公众号编辑器的 HTML。

我想要的不是"能转"，是"好看又能改"

很多现成工具只做到"能转换"，但风格是写死的。我的目标更高一点：好看、有个性、可定制。

于是我先把微信公众号的硬规则研究透了，做成了约束清单：

规则 公众号的要求
标题层级 <h1> 被禁用，最多用到 <h2>
容器 <div> 不可靠，要用 <p> 代替
样式 只能 inline CSS，不能用 <style> / class
交互 <script> / <iframe> 全部失效
图片 必须走公众号 CDN，SVG 保存即消失

⚠️ 注意
千万别在草稿里塞 <script> 或外链 SVG。前者被静默删除，后者保存瞬间消失，排版直接崩。这是血泪教训。

一条命令背后的流水线

整个流程其实只有五步，但每一步都卡着公众号的规矩：

  1. 读取 —— 识别 .md / .docx，统一转成原始 HTML
  2. 清洗 —— 删禁用的标签、把 <h1> 降成 <h2>、<div> 换成 <p>
  3. 上样式 —— 给每个元素挂上 inline CSS（按主题）
  4. 输出 —— 生成可直接复制粘贴的 HTML
  5. 发布 —— 浏览器里全选复制，粘进编辑器即可

对应的命令简单到一行：

python convert_to_wechat.py 我的文章.md 输出.html

我给这个技能加了什么

在原始 starter kit 的基础上，我新增了七项能力，让它从"能跑"变成"好用"：

  • 多主题：内置 default / accent / warm / minimal / forest 五套配色，一条参数切换风格
  • Callout 高亮框：用 :::tip :::warning :::knowledge 语法，一键生成提示、注意、知识点框
  • 自动目录：从 <h2> 标题自动生成「一、二、三」结构预览
  • 文章元数据：frontmatter 里写标题、作者、日期、摘要，自动生成头图区
  • 页脚版权：可自定义的版权声明，发布即带
  • 中文排版优化：中英文、数字之间自动补空格，专业感拉满
  • 图片内嵌：本地图片转 base64，生成自包含 HTML
